## Current Status

| Area                                                             | Status          | Notes                                                                                                                                                                                                                                                                                                                                      |
| ---------------------------------------------------------------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Repository and documentation                                     | **Implemented** | README, docs for architecture, database, API, security, development and deployment, and design docs for real-time and AI. Kept in step with the code.                                                                                                                                                                                      |
| Monorepo scaffolding (`apps/web`, `apps/api`, `packages/shared`) | **Implemented** | pnpm workspaces; shared TypeScript, ESLint, Prettier and Vitest config.                                                                                                                                                                                                                                                                    |
| Shared package (`packages/shared`)                               | **Implemented** | Zod schemas and inferred types for requests, responses, socket events and AI findings; the diff parser and view model; shared permission and approval-rule functions.                                                                                                                                                                      |
| API (Fastify)                                                    | **Implemented** | Validated env config, `GET /health` (liveness), `GET /ready` (checks Postgres and Redis), consistent error responses, graceful shutdown.                                                                                                                                                                                                   |
| Local infrastructure (Docker Compose)                            | **Implemented** | PostgreSQL 18, Redis 8 and Mailpit, bound to `127.0.0.1`.                                                                                                                                                                                                                                                                                  |
| CI (GitHub Actions)                                              | **Implemented** | Typecheck, lint, format check, tests (PostgreSQL 18 and Redis 8 service containers), API build and web build on PRs and pushes to `main`.                                                                                                                                                                                                  |
| Tests (Vitest)                                                   | **Implemented** | Unit tests, API integration tests against a separate test database and Redis (including a merge race test and real Socket.IO clients), and web component tests rendered to static markup. No coverage figures are claimed.                                                                                                                 |
| End-to-end tests                                                 | **Implemented** | Stage 9B: Playwright against the production builds of both apps, run in CI; fails on any CSP violation; `pnpm screenshots` writes the README images. See [development.md](development.md#end-to-end-tests-playwright).                                                                                                                     |
| Database (Drizzle)                                               | **Implemented** | Migrations `0000`–`0008`: users, sessions, verification tokens, workspaces, members, reviews, files, threads, comments, approvals, notifications, outbox, AI jobs, findings and feedback. See [database.md](database.md).                                                                                                                  |
| Authentication                                                   | **Implemented** | Register, login, logout and me (`/api/v1/auth/*`) with server-side sessions in HttpOnly cookies. Email verification: hashed single-use tokens (24 h), `verify-email` and `resend-verification` (once a minute); only verified users can be added to a workspace.                                                                           |
| Web pages (sign-up, login, profile)                              | **Implemented** | Sign-up, login, profile and logout; a verify-email banner with "Resend email"; a `/verify-email` page that verifies only after pressing Confirm.                                                                                                                                                                                           |
| Deployment (Vercel + Render + Neon)                              | **Implemented** | Web on Vercel; API, AI worker and outbox relay in one Render web service; Redis on Render Key Value; PostgreSQL on Neon. See [deployment.md](deployment.md).                                                                                                                                                                               |
| Workspaces and membership                                        | **Implemented** | Workspaces, roles (owner, admin, member, viewer), the `requireWorkspaceRole` guard, member management with the last-owner rule, and the web pages. **Remaining:** email invitations.                                                                                                                                                       |
| Reviews and diff ingestion                                       | **Implemented** | The diff parser, review endpoints (create, list with filters and cursor pagination, get, edit, close/reopen, delete, files, per-file hunks) and the web pages.                                                                                                                                                                             |
| Code diff viewer                                                 | **Implemented** | Unified and split views, a file sidebar, Shiki highlighting on the server, LCS word-level changes, line anchors and deep links, and "Load diff" for large files.                                                                                                                                                                           |
| Comments and threads                                             | **Implemented** | Line and review-level threads, replies, edit, soft delete, resolve/reopen, and suggested-change blocks (shown as a diff, copyable, downloadable as a patch). **Remaining:** review revisions and outdated detection.                                                                                                                       |
| Approvals                                                        | **Implemented** | Reviewer assignment, approve / request changes, per-workspace rules, merge under a row lock when the rules pass, review history; web panels, badges and list filters.                                                                                                                                                                      |
| Real-time collaboration (Socket.IO)                              | **Implemented** | Ticket auth, review rooms, the Redis adapter, live threads, review changes and AI status, presence, a Live / Reconnecting / Offline indicator. See [design/realtime.md](design/realtime.md).                                                                                                                                               |
| Notifications                                                    | **Implemented** | In-app notifications written with a transactional outbox, delivered live by a relay (`FOR UPDATE SKIP LOCKED`), and a header bell with an unread count and mark as read.                                                                                                                                                                   |
| AI analysis (BullMQ + LLM provider)                              | **Implemented** | Jobs table, BullMQ queue and in-process worker, OpenAI-compatible and fake providers, redaction, validated findings, retries and sweeper; the AI review card, inline findings, dismiss, start a thread, helpful / not-helpful feedback ([design](design/ai-analysis.md)). **Remaining:** the evaluation set and per-workspace AI settings. |
| Rate limiting and security headers                               | **Implemented** | Stage 9A: Redis-backed limits per IP, email and user; real client IPs through the web app; `@fastify/helmet` on the API; a nonce-based CSP on the web ([security](security.md#rate-limiting-and-security-headers-implemented)).                                                                                                            |
| Custom domain and real email sending                             | Planned         | Stage 9. Production writes verification links to the log (`MAIL_TRANSPORT=log`) until a domain and an email sender exist.                                                                                                                                                                                                                  |
| Application Dockerfiles                                          | Planned         | Only local Postgres, Redis and Mailpit run in Docker so far.                                                                                                                                                                                                                                                                               |
| OpenAPI documentation                                            | Planned         | To be generated from the Zod route schemas.                                                                                                                                                                                                                                                                                                |
| GitHub integration and OAuth                                     | Planned         | Stage 10.                                                                                                                                                                                                                                                                                                                                  |
| Email notifications and search                                   | Planned         | Stage 11.                                                                                                                                                                                                                                                                                                                                  |

Status labels used throughout: **Implemented** · **In progress** · **Planned**.

## Development Roadmap

| Stage                                | Scope                                                                                                                                                                                                                                                                                                                                                                                                                                                            | Status          |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------- |
| **0. Foundation**                    | pnpm monorepo; shared TypeScript, ESLint, Prettier and Vitest config; shared package; API and web skeletons; local Docker Compose; CI.                                                                                                                                                                                                                                                                                                                           | **Implemented** |
| **1. Database and auth**             | Drizzle schema and migrations; database connection; `/ready` probe; registration, login and sessions; sign-up, login and profile pages; free-tier deployment (Vercel, Render, Neon).                                                                                                                                                                                                                                                                             | **Implemented** |
| **2. Workspaces and roles**          | Workspaces, membership and role-based authorization guards. **Remaining:** invitations.                                                                                                                                                                                                                                                                                                                                                                          | **Implemented** |
| **3. Reviews and diff ingestion**    | Review creation from patch upload; the diff parser (`packages/shared/src/diff`); the `reviews` / `review_files` tables; review endpoints with cursor pagination; changed-file list; review web pages.                                                                                                                                                                                                                                                            | **Implemented** |
| **4. Diff viewer**                   | Unified and side-by-side diff views; file navigation; stable line references; syntax highlighting (Shiki) and intra-line (word-level) diff highlighting.                                                                                                                                                                                                                                                                                                         | **Implemented** |
| **5. Comments and threads**          | Review revisions (moved from Stage 3; needed for outdated detection); line-anchored comments, replies, resolution and outdated detection; suggested-change blocks in comments, shown as a diff and downloadable as a patch the author can apply with `git apply`. **Remaining:** revisions and outdated detection.                                                                                                                                               | **Implemented** |
| **6. Approvals and lifecycle**       | Reviewer assignment; approve / request changes; status recomputation; review history; configurable approval rules per workspace (required number of approvals, require all threads resolved), evaluated by a pure shared function.                                                                                                                                                                                                                               | **Implemented** |
| **7. Real-time**                     | First use of Redis: Socket.IO with ticket auth and rooms; emit-after-commit; presence derived from room sockets; in-app notifications through a transactional outbox; Socket.IO Redis adapter.                                                                                                                                                                                                                                                                   | **Implemented** |
| **8. AI analysis**                   | Job model; BullMQ queue (on Redis) and worker; provider adapter; context building and redaction; schema-validated findings; retries; findings UI; helpful / not-helpful feedback on findings and a fixed evaluation set of patches to measure prompt and model changes; per-workspace AI settings (enabled categories, minimum severity, opt-out), admin only. **Remaining:** the evaluation set and per-workspace AI settings.                                  | **Implemented** |
| **9. Hardening and deployment**      | Stage 9A done: Redis-backed rate limiting (per IP, per email, per user), real client IPs through the web app, `@fastify/helmet` on the API and a nonce-based CSP on the web ([security](security.md#rate-limiting-and-security-headers-implemented)). Stage 9B done: Playwright end-to-end tests in CI and generated README screenshots. Next: a custom domain (also required for sending email); then Dockerfiles, multi-instance deployment and observability. | **In progress** |
| **10. GitHub integration and OAuth** | Sign in with GitHub and Google (OAuth 2.0 authorization code flow with PKCE and state, linked to existing accounts by verified email, keeping server-side sessions); a GitHub App to import a pull request as a review, post AI findings back as review comments and commit accepted suggestions to the PR branch; webhooks with HMAC signature verification and idempotent processing.                                                                          | Planned         |
| **11. Email and search**             | Transactional email (email verification, password reset, invitation emails, review notifications and a daily digest with unsubscribe links) sent through a background job (Mailpit already catches local email); Postgres full-text search across reviews and comments.                                                                                                                                                                                          | Planned         |
